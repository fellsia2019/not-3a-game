# Not 3A Game

Изометрическая tower defense игра: герой добывает дерево, камень и металл,
строит башни и защищает трон. Целевая платформа первого выпуска — Windows;
разработку и просмотр проекта можно продолжить в Unity Editor на Mac. Сейчас
цель — один короткий понятный забег. Долгосрочный замысел и граница первого
играбельного билда описаны в [Game Vision](gamedesign/GAME_VISION.md).

## Состояние

Unity `6000.6.2f1`, URP, Input System. Stage 2 завершён. Текущая играбельная
визуальная проба Stage 3 — [Stage3Rapid3DGamePilot](Assets/Scenes/Stage3Rapid3DGamePilot.unity):
карта 250×250: плавная дорога по эскизу игрока, шириной около семи клеток,
занимает нижний левый район. Врата сверху слева, две низины и подъём посередине,
трон сверху справа; зелёный мир расширен вправо и вверх. Ресурсы и старт героя
сохранили координаты. В игре — мультяшные спрайты скелета, портала,
цели, башен и трёх ресурсов, трава и брусчатка по подборке B, мини-карта
снизу слева и зум колесом мыши или жестом на трекпаде Mac. Название сцены историческое: в ней сейчас
используются и 2D-спрайты. Проверка вида игроком и Stage 3 gate ещё открыты;
Stage 4 не начат. Точное состояние — в [плане](gamedesign/DEVELOPMENT_PLAN.md)
и верхнем handoff [Workstreams](production/WORKSTREAMS.md).

В Development Build кнопка «Дебаг» или F3 открывает меню: пауза, запуск
следующей волны, отдельные скорости героя/игры x1–x10, +100/+1000 золота или
каждого материала и рестарт. Открытие меню само не ставит игру на паузу.
Обычный HUD показывает ресурсы, волну, трон, строительство и исход забега;
технические таблицы с игрового экрана убраны. Бриф:
[HUD и дебаг-меню](gamedesign/features/STAGE3_DEBUG_MENU.md).

Ресурсные районы собираются процедурно из отдельных спрайтов: леса,
каменные массивы и шахты по 200–300 клеток. Новый запуск мира выбирает seed;
перезапуск забега сохраняет тот же мир. Для воспроизведения можно передать
`-worldSeed 164032`. Настройки и детали —
[генерация ресурсных зон](gamedesign/features/PROCEDURAL_RESOURCE_DISTRICTS.md).
Это визуальные районы для следующего шага экономики; обычная добыча пока
работает на прежних трёх узлах.
Каменные и железные районы непроходимы для героя. В лесу коллизия стоит у
каждого ствола, между деревьями можно ходить; при упоре герой скользит вдоль
препятствия. Радиусы настраиваются в ResourceDistrictArt.asset.
Рельеф районов теперь гибридный: объёмные уступы камня и выемка шахты со
связанными лестницами/площадками плюс рисованные деревья и декор. Лес оставляет
просветы; препятствия около героя становятся частично прозрачными с плавным
локальным переходом. Параметры формы и затухания — в том же data asset.

## Продолжение на Mac

На Windows и macOS используем одну точную версию Editor — **6000.6.2f1**
(revision `770e33f6875c`). Источник версии —
[`ProjectSettings/ProjectVersion.txt`](ProjectSettings/ProjectVersion.txt).
Обозначение «6.6» не определяет номер исправления: на Mac сверить полную
версию в Unity Hub. Обновление Editor проводить отдельно и согласованно для
обоих компьютеров: новая версия может преобразовать проект, после чего
возврат к старой не гарантируется ([документация Unity](https://docs.unity3d.com/Manual/TroubleShootingEditor.html)).

1. На Mac клонировать актуальную ветку `main` из публичного репозитория
   `https://github.com/fellsia2019/not-3a-game` (например,
   `git clone https://github.com/fellsia2019/not-3a-game.git`).
   Полный клон сохраняет историю Git; текущая рабочая копия не включает
   удалённые QA-записи. В Git сохранены
   `Assets/` с `.meta`, `Packages/`, `ProjectSettings/`, `art/`, вся проектная
   документация и `concepts_visual_scene/`. Для дальнейших обновлений в
   этой папке использовать `git pull --ff-only`.
2. Установить Unity Editor **6000.6.2f1** через Unity Hub и открыть клонированную папку
   проекта. Unity восстановит `Library/` и пакеты из `Packages/manifest.json`
   и `Packages/packages-lock.json`; первый импорт может занять время.
3. Открыть сцену `Assets/Scenes/Stage3Rapid3DGamePilot.unity` и запустить
   Play. Для привычного обзора есть меню `Tools > Stage 3 > Cartoon World >
   Open Live Review` — оно показывает начало дороги у портала. Для просмотра
   ресурсов есть `Tools > Stage 3 > Resource Sprites > Open Live Review`,
   а в Play — команды `Frame Wood`, `Frame Stone`, `Frame Iron Ore` в том же меню.
   Если меню ещё не появилось, дождаться импорта и компиляции скриптов.
4. Проверить Game view и Console. Сборки в `Builds/Windows/` и журналы в
   `Artifacts/` локальны и в перенос не входят. Разработка на Mac не меняет
   принятую целевую платформу Windows; выпуск или QA сборки macOS отдельно
   не утверждались и не проверялись.

Для зума на трекпаде щёлкнуть по Game, оставить курсор над игровой областью
и разводить/сводить два пальца. Проверенный пользователем macOS-плагин уже
включён в Git вместе с исходниками; на Windows он исключён настройками импорта.
Управление камерой и пересборка плагина описаны в
[Tactical View](gamedesign/features/STAGE3_TACTICAL_VIEW.md).

Последняя проверка на Mac 15.10.2026: Unity 6000.6.2f1 ARM64, Apple M3/Metal;
Stage3/Integration/RunState PlayMode — **46/46**, после внедрения спрайтов
ресурсов. Проверены также мини-карта, ввод, строительство, бой и полный забег
с перезапуском. В живом Game просмотрены все три ресурса; Console —
0 ошибок/0 предупреждений. Результаты и кадры сохранены в Git в `art/review/`,
включая [сводку проверки](art/review/resource_sprites_2026-10-15_verification.json).
Детали — в верхнем [handoff](production/WORKSTREAMS.md); локальные логи/XML —
`Artifacts/S3-RESOURCE-SPRITES-20261015/`. Исходная проверка переноса на Mac
(41/41) сохранена отдельно в `Artifacts/S3-MAC-20261015/`.

### Работа попеременно на Windows и Mac

- Использовать Unity **6000.6.2f1** на обоих компьютерах и сохранять версии
  пакетов из `Packages/`. Кэш `Library/` каждый компьютер создаёт сам.
- Перед продолжением работы остановить Play, сохранить и закрыть Unity,
  проверить `git status` и получить изменения через `git pull --ff-only`.
  Локальные незавершённые изменения сначала сохранить в своей ветке/коммите.
- После работы сохранить сцены/ассеты, проверить diff, затем сделать commit и
  push своей ветки. На другом компьютере сначала получить этот commit.
  Для параллельных изменений использовать разные ветки; одну сцену или prefab
  согласованно редактировать на одном компьютере за раз.
- Переносить `.meta` вместе с ассетами. `Library/`, `Temp/`, `Logs/`,
  `UserSettings/`, `Builds/` и `Artifacts/` уже исключены из Git; копировать их
  между ОС не требуется. В проекте включены Visible Meta Files и текстовая
  сериализация; `.gitattributes` закрепляет LF для сцен, ассетов и кода.

Оригинальная подборка B —
`art/concepts/sprite_style_review_2026-10-15/b_cartoon_2d.png`;
приложенный позднее вариант имеет те же пиксели. Остальные концепты,
промпты, файлы происхождения генераций и кадры из игры — в `art/`.
`art/source/*provenance.json` может содержать старые абсолютные Windows-пути
к файлам генератора; используемые PNG уже находятся в `Assets/`, а исходные
концепты — в `art/`, поэтому эти пути на Mac не требуются. `art/review/`
содержит статичные кадры проверок; ненужные анимированные записи удалены по
запросу владельца.

Исторические сторонние референсы в `concepts_visual_scene/` находятся вне
`Assets/` и не являются игровыми ассетами. Их источники/лицензии не подтверждены;
список каждого файла и его статус — в [индексе](concepts_visual_scene/README.md).
То же относится к присланному референсу в `art/references/`. По явному решению
владельца D-044 эти материалы сохранены в публичном GitHub вместе с проектом,
но для включения в игру нужна отдельная проверка прав. Генерируемые `Library/`, `Temp/`,
`Logs/`, `Builds/` и `Artifacts/` восстанавливаются или не нужны на другом
компьютере.
